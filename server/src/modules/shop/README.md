# Milestone 3 Task 6: shop integration

All routes below are relative to `/api/game/shop`. Every route authenticates, locks the character row inside a transaction, validates a shared Zod schema and has its own rate-limit entry. Mutations return `{character, completed, rewards, levelsGained}`; selling also returns `earned`.

| Route                  | Request                       | Response / original rule in shops.md                                                                                                                                                                                                                     |
| ---------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `/open`            | Empty query                   | `{tabs, wholesale, sellable}`. Wholesale shop level band; Refresh shops, Restock triggers: open uses strictly more than 1800 seconds. Refresh tabs are types 1, 3, 2; Wholesale is the fourth client tab.                                                |
| POST `/wholesale/buy`  | `{itemId, count}`             | Wholesale shop, Buy: bound stacked items, total price, atomic bag/currency check. Box 1001 sells i160006 at 38 Stone.                                                                                                                                    |
| POST `/refresh`        | `{shopType, mode: "countdown" | "instant", currency}`                                                                                                                                                                                                                                    | Refresh shops, Restock triggers: countdown uses at least 1800 seconds; instant supports configured currency choices and one daily free restock where configured. Returns the shop view with the mutation result. Free resets at UTC midnight (decision 4). |
| POST `/buy`            | `{shopType, slot, currency}`  | Refresh shops, Buy one item: the slot moves once, including binding, appraisal and properties.                                                                                                                                                           |
| POST `/buy-all`        | `{shopType}`                  | Refresh shops, Buy all: all currency totals and all bag space checked before moving stock.                                                                                                                                                               |
| POST `/sell`           | `{inventoryId, count}`        | Selling to NPCs: unequipped owned item, CanTrade bit 1, Price times count Stone. Binding does not prevent sale.                                                                                                                                          |
| POST `/sell-all`       | `{inventoryIds}`              | Selling to NPCs, Sell all: listed sellable bag stacks are destroyed; ineligible rows are skipped. Duplicate IDs are rejected.                                                                                                                            |
| POST `/pouches/refill` | `{currency: "gold"            | "giftCoupon", hp, mp}`                                                                                                                                                                                                                                   | Pouch refill: numeric units of 1000; -1 fills; 0 skips; no VIP discount. Compatible M2 `/api/game/pouches/buy` remains available.                                                                                                                          |
| GET `/merchant`        | Empty query                   | `{available:false}` outside scheduled hours, otherwise `{available:true, spawnId, sceneId, endsAt, stock, vipStock, vipAvailable:false}`. Mysterious Merchant: 09:00–23:00 UTC, first ten minutes, random scene 2601–2605; historical end dates ignored. |
| POST `/merchant/buy`   | `{spawnId, tab: "gold"        | "vip", slot, count}`                                                                                                                                                                                                                                     | Mysterious Merchant, Buy: scene/time/level checks, per-item player limit for each spawn, bound stacks, Gold check. Spawn row lock serializes server stock. VIP currently refused.                                                                          |

`GET /open` accepts an optional `tab` query parameter (1–4). Opening tab 2 records tutorial command 2109 and includes the updated character and quest rewards.

`currency` is `stone`, `gold` or `giftCoupon`. Refresh buy checks that the selected currency is present and charges the complete row price. Restock currency choices are alternatives. Merchant Gold prices are snapshotted from server-wide earlier sales for each spawn; repeated item rows keep separate stock and share the player limit. Lazy spawn creation uses a PostgreSQL transaction advisory lock; spawn and sales persist across process restarts.

Draws and formulas live in `game-core/src/economy/shops.ts`, imported directly because changing the game-core package index is outside folder ownership. Item Shop appraisal uses the existing equipment `rollIdentify` implementation and imported identify tables. Daily free state uses the existing `free_restock_day` column; all current pools allow at most one free restock.

## Window wiring (task 8)

Import `ShopWindow`, `MerchantWindow`, `PouchRefillDialog`, `useOpenShop` and `useOpenMerchant` from `client/src/game/shop`.

Keep both hooks mounted in the window registry. `useOpenShop()` returns `{isOpen, initialTab, open(tab = 1), close}`; tabs 1/3/2/4 are Item/Dark/Mystery/Wholesale. When open, render `<ShopWindow character={character} initialTab={shop.initialTab} onClose={shop.close} />`. `useOpenMerchant()` returns `{isOpen, open, close}`; render `<MerchantWindow character={character} onClose={merchant.close} />` while open. Connect merchant-boss menus and town shop controls to `shop.open`, Dark to `shop.open(3)`, Mystery to `shop.open(2)`, Wholesale to `shop.open(4)`, and timed merchant NPC n28001 to `merchant.open`. In neutral scenes, query `/api/game/shop/merchant` to discover the active scene and expiry before showing n28001; polling this endpoint initializes the persistent hourly spawn. The pouch HUD can mount `PouchRefillDialog` with the same character and close callback. The shop window also opens this dialog itself. Hooks use the existing query cache and apply mutation character results to the HUD.

No changes were made to GameApp.tsx or Hud.tsx.

## Deferred and schema limitations

- VIP merchant purchasing: characters have no `vip_until` or membership field. The original VIP stock is visible but locked; task 11 supplies membership. Gold-tab merchant rules are complete.
- Paid Mystery Shop restock achievement 14: no achievement counter/table exists in the current schema. Currency spending and restocks work; tracking waits for the achievement system.
- Expired inventory-item sale refusal: inventory_items has no expiry timestamp or per-instance timer. CanTrade and equipped checks are implemented; expiry cannot be reconstructed safely from item configuration alone.
- Timed merchant scene rendering and announcements: the persistent spawn is initialized when the merchant endpoint is queried; task 8 owns scene/NPC/window integration. No background broadcast scheduler was added in another owner's folder.
- Mall, player market, player trade and buy-back are outside Task 6 scope; the original has no buy-back.

Outside owned folders: only server/src/app.ts (one registration statement), shared/src/index.ts (one re-export) and server/src/modules/game/rate-limits.ts (added route entries). No migrations, schema, game progress modules or top-level client game files changed.
